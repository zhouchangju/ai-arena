# macOS 构建与排障

这是一个使用系统 WebKit 的原生 macOS 应用。一个窗口里有 ChatGPT、Gemini 和 DeepSeek 各自的真实网页。流式正文、图片、表格、引用和交互控件由各站渲染。工具栏负责组织轮次，讨论记录保存在本机。

从源码构建后，默认应用包位于 `desktop/build/AI Arena.app`。构建版本以 [Info.plist](Info.plist) 为准。 [0.3.0 开场界面](../docs/evidence/native-0.3/composer.png) · [0.3.0 讨论界面](../docs/evidence/native-0.3/discussion.png)

## 第一次使用

1. 双击 `AI Arena.app`，在各席原页里按站点提示登录。应用使用自己的持久 WebKit 数据存储，需要在这个应用里建立登录会话。
2. 选择两席或三席，在多行框输入问题，点「开始讨论」或按 ⌘↩。开始后题面收起，让出空间给三席原页。每个参与席在自己的原页接收提示。独立作答后，工作台向各席转交其他席位的回答，起草候选并请各席对同一版本表态。「互评上限」控制最多几轮互评：每一轮从互评开始，之后起草或修订候选并请各席表态；独立作答阶段不显示轮号。开始互评后，阶段、报告和导出均显示「互评第 N 轮 / 上限 M」。默认 3 轮，可选 1–5 轮。仍有反对或附加条件时，在剩余轮次内定向互评并修订；全体明确同意可提前结束，到上限则列出未决分歧。窗口缩到约 860 点宽时，三席仍保持整列全高并横向滚动，不会压成两行半高页面。只剩两席时，再点已选席位会提示「至少保留两席」，不会静默无反应。
3. 每席顶部用固定类别显示状态：待发送、生成中、已收到、需要你处理、已接管、已跳过、已暂停、已完成。具体原因放在第二行或悬停说明里，颜色和短标签只由类别决定。「查看当前提示」可核对材料。「暂停」用于暂停后续派发，阶段标记会同时变为暂停色；已经发送给原站的请求仍可能生成。某席遇到登录、限流或页面变化，可以在该席菜单中接管、补录或跳过。菜单项按当前状态启用：接管只在尚未接管时可用，补录只在有当前待处理任务时可用，恢复只在已接管或受阻时可用；「跳过本席」需确认，并计为缺席。接管只切换状态，补录面板不遮挡原页，预填已保存回答；尚未保存时使用最新流式预览，并标注「部分预览」。核对原页后可选择「恢复本站自动」。发送结果不确定时，工作台回到同一会话核对本轮提问和随后出现的原始回答。Gemini 正文停止变化却缺少完成标记时，工作台会在确认没有生成控件和未发送草稿后尝试重新读取原页。原页的确认框和输入框以窗口内表单出现，不阻塞其他席位；需要弹出窗口的站点登录会打开独立子窗口完成回调。
4. 前台讨论结束并保存后会打开报告。报告保存后，顶部操作栏提供「查看报告」主按钮，可直接打开报告标签；已完成场次和只读回看同样可用。Arena 在后台时，完成提醒由 macOS 通知送达。也可从「详情」查看发言、互评、表态和报告，用「导出」保存 Markdown。「历史」打开已有记录，条目显示日期时间和结果状态；已完成场次只能回看，未完成的场次可在新建、关闭窗口或退出后从历史选择「继续这一场」，沿用只读核对、绝不重发的续跑路径。应用重启会恢复上次讨论；未完成席先进入人工核对，避免重复发送。讨论运行中「新建」「结束」或关闭主窗口都会先确认：「结束」结束整场且之后不能继续，只能从历史回看；关闭窗口或退出确认后不再发起新的发送，但已发送的请求仍可能在原站生成。记录默认存放在 `~/Library/Application Support/AI Arena/`。 [通知权限和报告操作](../docs/try-it.md#阅读并导出报告)

首次登录需要站点本人验证。Google 可能限制嵌入式 WebView 登录。已在本机登录态核对三站的原页收发；具体轮次与覆盖见[站点验证](../docs/provider-validation.md)。 [Google 授权说明](https://developers.google.com/identity/protocols/oauth2/native-app#disallowed_useragent)

开场可粘贴多张截图或添加小型文本文件，具体格式和操作见[带图或文件提问](../docs/try-it.md#带图或文件提问)。

## 最终报告怎么来

起草席收到带有来源编号的讨论原文，用它写出建议回答、成立条件、反例和分歧。每一席都对同一版本的完整候选表态。工作台核对参与记录、候选版本、正文摘要值及明确票态，再把结论、逐席意见与来源编入报告。页面上的“全体一致”表示各席在这次讨论中达成一致，外部事实仍需按引用核实。

新候选按「直接建议」「成立条件」「影响建议的未决分歧」组织，报告正文开头显示这三部分。点「图解」可沿条件和分歧查看候选原文与出处。「离线 HTML」可保存为独立网页，在浏览器展开原文并跳转引用，文件包含题面和发言文本。「讲解视频」在本机生成可保存的字幕 MP4，依次呈现场次状态、建议、条件与分歧。系统可从完整候选格式识别三部分时显示这些入口，其余报告可继续按原样阅读和导出 Markdown。

详情在独立的 macOS 窗口中打开。先读建议和各席表态，需要核对时再展开发言、互评和出处。复制报告和导出 Markdown 都可取得完整材料，包括往轮中提出的反例。三个详情标签使用系统分段控件，「原始记录」（JSON）收在旁边的「更多」菜单里。窗口可以拖动边缘调整大小，绿色按钮可进入全屏，标题栏双击遵循 macOS 的系统设置。点击正文中的来源编号（如 [S1]）可以查看对应发言。导出中的结果状态按保存的场次（最终表态、跳过或未完成）生成，不使用界面上的临时状态；场次编号只出现一次；时间使用本机时区并带偏移。 [0.4.0 报告窗口示例](../docs/evidence/native-0.4/report.png)

## 一席停住时怎么看

| 席位状态 | 原页上发生了什么 | 如何处理 |
|---|---|---|
| 需要你处理 · 等待发送控件 | 提示已写入编辑框，工作台正在等发送控件就绪。 | 先等自动重试。若长时间未就绪，在该席菜单接管，核对原页上的草稿或已发消息。 |
| 需要你处理 · 发送结果待确认 | 点击可能已到达站点，工作台正在查找本轮原始提问及随后出现的答复。 | 保持当前会话，让工作台读回，避免手动再发一遍。 |
| 需要你处理 · 缺少明确立场 | 本轮表态未能解析出同意、有条件同意或反对。 | 查看原文，只在立场明确时接管并选择相应表态；无法判断时可跳过，该席计为缺席。 |
| 需要你处理 · 图片待核对 | 原页缺少图片，或无法确认已发消息带齐本场图片。 | 核对本席原页的草稿、已发消息及附件。已发出的题面先查回执；若无法确认，可跳过本席。 |
| 已接管 | 该席已停止自动派发，补录面板可用。 | 核对原页后补录原文，或恢复本站自动。 |
| 已跳过 | 该席本轮计为缺席，不会计入同意。 | 需要时可在后续轮次重新参与，报告保留缺席记录。 |

## 构建和验收

需要 macOS 13 或更新版本、Xcode 或 Command Line Tools 提供的 Apple Swift 工具链，以及 Node.js。在仓库根目录执行：

```sh
./desktop/build.sh
open "desktop/build/AI Arena.app"
```

构建使用 Apple Swift 工具链、系统框架和 Node.js，生成本机架构的本地签名应用。构建脚本把已有讨论引擎、网页驱动和站点配置装入应用资源目录。运行时只需要 macOS；目前实测机器为 Apple Silicon。

如果 macOS 27 的 Command Line Tools 报缺少 `SwiftUIMacros`，本机安装有 26.5 SDK 时，可为这次构建指定 SDK。

```sh
SDKROOT="$(xcrun --sdk macosx26.5 --show-sdk-path)" ./desktop/build.sh
```

如果 26.5 SDK 的 WebKit 接口与当前 Swift 编译器不兼容，可使用 Xcode 自带的 SDK。0.5.0 使用 Xcode 的 26.1 SDK 完成构建。

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
SDKROOT="$(xcrun --sdk macosx --show-sdk-path)" ./desktop/build.sh
```

共享讨论引擎测试可直接运行 `node --test tests/core.test.mjs`。

日常调试需要 WebKit 时，在临时目录构建并由 QA 脚本启动。下面的命令可在后台运行，包含一次完整讨论、报告和重启检查。

```sh
qa_dir="$(mktemp -d)"
ARENA_SIGN_IDENTITY=- ./desktop/build.sh "$qa_dir" &&
  python3 tests/native_desktop_acceptance.py --app "$qa_dir/AI Arena.app" --out "$qa_dir/results"
```

原生隔离验收需要 Python 3。脚本用共用回环夹具在 macOS WebKit 中运行。单独的网页驱动测试还需要 Playwright Python 包和本机 Chromium。原生验收的输出目录请使用新路径。

```sh
python3 tests/native_desktop_acceptance.py --app "desktop/build/AI Arena.app" --out /tmp/arena-native-full
python3 tests/native_desktop_acceptance.py --app "desktop/build/AI Arena.app" --out /tmp/arena-native-takeover --takeover
python3 tests/native_resume_acceptance.py --app "desktop/build/AI Arena.app" --out /tmp/arena-native-resume
```

这些命令会从指定的应用包复制出 AI Arena QA，使用独立的应用标识、WebKit 资料和临时讨论目录访问回环测试页。三条命令依次覆盖完整讨论与导出、单席接管、中途重启。重启用例从两席已答、第三席待发的记录继续，核对已答席位的重复发送次数。

附件验收使用独立的临时场次目录，默认检查原生剪贴板、多图投递、单席异常、图片错序和重启核对。将 Xcode 作为工具链后运行以下命令。

```sh
python3 tests/native_attachment_acceptance.py --app "desktop/build/AI Arena.app" --out /tmp/arena-native-attachments
```

## 运行时和钥匙串

桌面调度器监控原页是否真正送达和答完，JavaScriptCore 中的本地状态机组织互评、候选、确认与报告。参与讨论的网页 AI 负责观点、互评、修订及表态。共享引擎在调用方未显式指定轮次时保留旧版 2 轮上限，未传轮次的旧场次续跑沿用这一行为；桌面版新场次单独显式传入 3 轮，因此界面显示默认 3 轮。

macOS 的“AI Arena WebCrypto Master Key”用于 WebKit 持久化网页加密密钥。“始终允许”受 macOS 对应用签名身份的检查约束。使用同一份已授权应用通常不需要重复输入。默认临时签名与构建内容绑定，更新后可能再次询问。如果已有有效的代码签名证书，可将 `ARENA_SIGN_IDENTITY` 设为该证书身份，后续版本使用同一身份和应用标识构建。指定身份无效时构建会失败。 [Apple 的签名身份说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements/)
