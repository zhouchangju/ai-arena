# 迭代与验收记录

记录按时间顺序保留。早期轮次对应 Chrome 扩展，自「原生 macOS 单窗工作台」起记录桌面版。当前使用入口见[试用指引](try-it.md)。早期记录保留当时的界面用词（如“质询”“表决”）；当前版本统一为“互评”“表态”，内部阶段键不变。

## 2026-11-21 · 第一轮 · 双席讨论

**目标**　G1–G4。用户能在本地 Chrome 中从同一题面开始，比较两份独立答复、互相质询、对同一份候选作出明确表态，并导出含原文依据的结论。

**执行与复核**　独立任务为轮次引擎、后台和站点登记、工作台界面、浏览器验收，以及获准网页的读写驱动和本地样本。总指挥检查接口与实际效果。

**验收方法**　从真实加载的扩展页创建讨论；核对第二轮提示中出现对方发言，检查全体同意和保留分歧的不同结果；重开工作台并比对历史和导出。样本页面、账号实测和本人盲评分别登记。

**实际结果**　冻结首版文件并在隔离配置的 Chromium 里加载。26 个核心用例通过，浏览器验收 48 项通过，覆盖真实点击、两席互评中对方独有文字、显式表态、导出、刷新、另一窗口读取同一份报告。输入为合成样本，网络检查记录零次外部请求。观察到原后台会丢失来源 ID，已移除备用状态机；浏览器复查任务带 S1。中段反例、无效来源、缺出处降为草稿均有核心回归。

**反思**　个人已可使用两个网站的手动回复完成一次可追溯判断。手动往返仍然费时，首页在 1280×800 的视口首先展示大面积站点卡，输入和开始操作较靠下。下一轮应验收已获准网页的自动收发，同时压缩首屏。自动驱动和接线的并行预研尚待集成，本轮仅提交手动路径。

## 2026-11-22 · 第二轮 · 网页自动接力与首屏

**目标与验收**　G1/G3 在两个明确配置的本机页面实际填写、提交、采集七份结果并生成结论。G2/G4 首页首屏可输入问题、选择成员、开始，报告引用能定位到原文。原生网站按已确认能力显示手动交接。自建网页样本的完整自动通过也不能据此标记消费网站已通过。

**已发现并派修**　原验收脚本的等待方法触发扩展 CSP，测试配置的 DNS 规则还阻断了回环页面。分别更换为直接轮询与本机连接。受控网页实测先走到了表态阶段，随后发现后台从单个待办读取阶段，而该阶段实际保存在场次上，导致缺少 stance。另修正两席都回答时把收件人自己列为缺席、用户提前结束丢失待处理席位的报告问题。未修改站点安全策略。

**结果与复验**　37 个核心及标签用例通过。真实 Chromium 中，手动路径 62 项检查通过；本机两页分别在 DOM 接受了 4 和 3 次提交，共七条不同投递，最终两席明确确认同一候选。自动路径通过的是专用测试副本，仅预授回环站点权限；正式扩展仍按用户点击请求。手动测试无外发，自动测试只访问本机页面。并发打开同一席只有一个标签，把标签导航到另一站后再打开该席会保留被挪用的标签。桌面 1280×800 首屏可见输入与开始操作，报告引用可跳到有编号的历史原文。检查了窄屏无横向溢出。 [确定性网页样本导出](evidence/sample-report.md)

**反思**　这版解决了手工传话和受控网页自动传话两种路径。实际判断变化时，用户仍缺少把新增条件带到下一阶段的入口；普通网页的复制和打开也分成两个动作。下一轮优先补这两处，不扩展站点数量。真实账号结果和六题盲评留待本人。

## 2026-11-22 · 第三轮 · 用户补充条件与手动交接

**目标与执行**　G1/G2/G3 在暂停的独立作答或质询阶段允许补充判断条件，记录归属，后续新任务使用；G1/G4 合并复制与打开原页的重复操作。协议与存储、界面与交接、独立浏览器验收分别由执行者承担。开发后须比对新增条件前后两份已有原文、下一轮两席的实际提示及最终报告，不只看按钮是否出现。

**结果与复验**　从最终工作树复跑，52 个核心与标签用例、61 项手动路径浏览器检查、13 项补充条件与交接检查均通过。自动路径在预授回环权限的测试副本通过全部检查。已直接核对真实 DOM 上两席共七次提交、逐席表态、最终保存与导出的数据。剪贴板逐字等于当前席位提示。两次交接只打开一个目标标签；重复打开扩展使用同一工作台，实测保留场次 URL。新条件在本轮已有提示中没有出现，在后续两席的质询提示、刷新后的记录、最终报告与 Markdown 中均可找到。 [导出样本](evidence/sample-report.md)

**失败与修正**　为验收预先创建的场次只切了 URL 片段，测试页未重新读取场次，改为重开该路由后核实状态。剪贴板验证改用独立浏览器配置并聚焦工作台，逐字比对，取消跳过。原定演示端口 8765 已有其他服务使用，预设与指引改为 8877，已取到带样本标识的 HTTP 页面并释放本次服务。

**停止决定**　完成三轮后交付本人试用。当前最有价值的新证据是常用真实账号跑一场、原生授权框体验，以及六题盲评中是否比单模型和普通汇总多纠正了错误。样本页无法替代这些判断。九个公共网站目前均为手动交接；第三席、任意远程站点自动驱动、附件、可选裁判与自定义轮数未交付。未运行线上发布或远程推送。试用后根据具体卡点重排优先级。

试验服务已关闭。

## 2026-11-22 · 第四轮 · 界面与实际操作

**目标**　G1/G3/G4。缩短重复开场与手动交接的路径，给桌面和小屏做适合长时间阅读的玻璃风格界面；把页面文字改成能直接说明下一步的中文。

**参照与执行**　总指挥在隔离 Chromium 加载了参考项目的 popup.html，核对了推荐组合、带图标的成员选择、底部操作和目录入口。视觉样式、品牌标识、文案、交互、小屏导航、回归检查分别由独立执行者承担。验收以实际提问、回填、互评、表态和查出处为准，并对照浅色、深色和窄屏截图。

| 使用场景 | 与参照版的比较 | 本轮取舍与复验 |
|---|---|---|

**失败与修正**　第一稿小屏历史占位太大；玻璃素材首稿像平面色块，第二次用实际光照渲染。复核还发现跳过后错误承诺可以补录、换成员提示与操作冲突、展开编辑时重复跳过及可选控件泄露 null。已逐项修复并回放。未提交草稿和已提交更正分开保存。

**验收与停止**　57 个核心及标签用例通过。独立 Chromium 回放通过 61 项手动流程、39 项交互与外观检查、37 项操作修复验证、25 项回答更正验证；补充条件与本机自动接力也通过。复验覆盖浅色、深色、390px 窄屏、提交状态、重新打开、逐席确认与引用跳转。本机自动接力依然使用预授回环权限的测试副本与确定性页面。本轮只对比参考项目的实际界面、入口与代码，没有用真实账号重测公网自动收发。

## 2026-11-22 · 第五轮 · Bombadil 属性测试与草稿修复

**目标**　G1–G4，重点是 G2/G3/G4。用户应能收起和恢复刚录入的草稿；清除表态草稿应同时清掉立场与理由，避免下次仅输入理由就沿用旧表态。用合成双席讨论探索暂停、恢复、回填、清除、刷新、投票与报告，再到真实扩展页逐步核对故障。

**安装与接线**　安装 Apple Silicon 官方发布的 Bombadil 0.8.0 并核对本地版本。GitHub 发布件 SHA-256 为 `2ea26a68ac9b5296a8828ff138fb17a3343f7e8cf50647e9d1a81074505f995c`，本地核对一致。上游的 URL 规则只接受 HTTP(S) 和 file，`chrome-extension://` 默认报 invalid scheme，`<all_urls>` 也不包含扩展协议。测试入口以 Chromium 路由在回环地址提供原工作台文件，将受限的消息转给同一测试浏览器里的真实 MV3 后台。独立配置无登录态，未匹配的 HTTP(S) 请求会被拦截。这一入口改变了页面的来源和消息传输，真实扩展页另用原生消息回归。 [发布版本](https://github.com/antithesishq/bombadil/releases/tag/v0.8.0) · [上游 URL 匹配实现](https://github.com/antithesishq/bombadil/blob/v0.8.0/lib/bombadil-browser/src/match_pattern.rs)

**验收**　基线为 `4a9d0b8`。同一套 Bombadil 规格在基线重新触发收起违规，修复后分别在 1280×800 和 390×800 探索 35 秒，最终的 `final-desktop.bin` 和 `final-narrow.bin` 分别记录 444 与 470 个状态，均为零违规。两次都走过独立作答、交叉质询、候选与逐席确认，桌面到达「全体一致」，窄屏到达「仍有明确反对」。两次分别触发 12 和 14 次清除确认。同一份定向浏览器回归在基线为 42/49，修复后为 49/49。手动主流程 61/61，核心和标签 57/57，UX 走查 39/39，回答更正 25/25，补充条件与交接 13/13。本机自动双席通过，实际七次唯一提交。补充条件脚本早期运行在关闭时有 Playwright 路由清理日志。启用 DNS 阻断的最终复验验证了复制内容和标签复用，模拟页面的路由命中为零。

## 2026-11-22 · 第六轮 · 三席讨论和真实账号预检

**目标**　G1–G4。用 ChatGPT、Gemini、DeepSeek 在同一场讨论中独立作答、交叉质询、对同一份候选明确表态，并保存结论和 Markdown。三席和双席沿用同一套轮次与版本规则。

**账号预检与交接**　在已授权的浏览器任务空间访问三个原站。ChatGPT 与 Gemini 呈现可用输入框。DeepSeek 跳转到手机号／验证码登录页，已把浏览器交回本人完成登录。本轮尚未向三个账号发送题面或回答。真实讨论、真实结论与其导出仍待登录后实跑。浏览器任务空间保留在本人控制下。

**修订**　原首页、后台和引擎都限定恰好两席。本轮支持选两席或三席、拒绝第四席、恢复上次实际开场的组合。三席均收到相同题面，每席质询带另外两份原文，起草者也对同一候选投票。使用现有本地自动席配置。Bombadil 通过回环测试入口驱动页面，按待办号保存实际提示和哈希，只接收对应的原文回复；手动席与浏览器交接由测试端处理。日志与回复文件位于仓库外。

**验收与修复**　在 390×800 的隔离浏览器中，用本地合成回复完成 10 个待办，独立作答 3 份、质询 3 份、候选 1 份、针对 v1 的表态 3 份。两席同意、第三席有条件同意，报告显示「有条件一致」。逐条核对回填文本、两份对方原文、候选摘要和 10 个来源编号，Bombadil 记录 23 个状态、零属性违规。首次尝试只改 URL 片段，原生扩展页没有重新加载该场，改为打开一个新扩展页。第二次在 Bombadil 改过下载目标后捕获到空文件，改为点击原生导出按钮，读取该按钮生成的 Markdown Blob，校验题面和来源编号后保存。最终样本 18,506 字节。双席原生文件下载另由手动主流程覆盖，61/61。双席草稿回归 49/49，UX 走查 39/39，核心和标签 58/58。通用 Bombadil 规格复跑另外记录 424 个状态、零违规。核心定向用例还验证了第三席缺席不能形成全体一致。
