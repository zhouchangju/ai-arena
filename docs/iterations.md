# 本地开发记录

## 2026-11-21 · 第一轮 · 双席讨论

**目标**　G1–G4。用户能在本地 Chrome 中从同一题面开始，比较两份独立答复、互相质询、对同一份候选作出明确表态，并导出含原文依据的结论。

**分工**　OpenCode Go / DeepSeek V4.1 Flash / high。独立任务为轮次引擎、后台和站点登记、工作台界面、浏览器验收，以及获准网页的读写驱动和本地样本。总指挥检查接口与实际效果。

**验收方法**　从真实加载的扩展页创建讨论；核对第二轮提示中出现对方发言，检查全体同意和保留分歧的不同结果；重开工作台并比对历史和导出。样本页面、账号实测和本人盲评分别登记。

**实际结果**　冻结首版文件并在隔离配置的 Chromium 里加载。26 个核心用例通过，浏览器验收 48 项通过，覆盖真实点击、两席互评中对方独有文字、显式表态、导出、刷新、另一窗口读取同一份报告。输入为合成样本，网络检查记录零次外部请求。观察到原后台会丢失来源 ID，已移除备用状态机；浏览器复查任务带 S1。中段反例、无效来源、缺出处降为草稿均有核心回归。

**反思**　个人已可使用两个网站的手动回复完成一次可追溯判断。手动往返仍然费时，首页在 1280×800 的视口首先展示大面积站点卡，输入和开始操作较靠下。下一轮应验收已获准网页的自动收发，同时压缩首屏。自动驱动和接线的并行预研尚待集成，本轮仅提交手动路径。

## 2026-11-22 · 第二轮 · 网页自动接力与首屏

**目标与验收**　G1/G3 在两个明确配置的本机页面实际填写、提交、采集七份结果并生成结论。G2/G4 首页首屏可输入问题、选择成员、开始，报告引用能定位到原文。原生网站按已确认能力显示手动交接。自建网页样本的完整自动通过也不能据此标记消费网站已通过。

**已发现并派修**　原验收脚本的等待方法触发扩展 CSP，测试配置的 DNS 规则还阻断了回环页面。分别更换为直接轮询与本机连接。受控网页实测先走到了表态阶段，随后发现后台从单个待办读取阶段，而该阶段实际保存在场次上，导致缺少 stance。另修正两席都回答时把收件人自己列为缺席、用户提前结束丢失待处理席位的报告问题。未修改站点安全策略。

**结果与复验**　37 个核心及标签用例通过。真实 Chromium 中，手动路径 62 项检查通过；本机两页分别在 DOM 接受了 4 和 3 次提交，共七条不同投递，最终两席明确确认同一候选。自动路径通过的是专用测试副本，仅预授回环站点权限；正式扩展仍按用户点击请求。手动测试无外发，自动测试只访问本机页面。并发打开同一席只有一个标签，把标签导航到另一站后再打开该席会保留被挪用的标签。桌面 1280×800 首屏可见输入与开始操作，报告引用可跳到有编号的历史原文。检查了窄屏无横向溢出。[工作台截图](evidence/workspace.png) · [报告截图](evidence/report.png) · [确定性网页样本导出](evidence/sample-report.md)

**30 分钟自检**　00:06 已核对实际进程、文件状态、套餐额度和阻塞原因。合并了重复职责，结束已完成的执行者；保留主路径验证。没有重新启动同一开发任务。

**反思**　这版解决了手工传话和受控网页自动传话两种路径。实际判断变化时，用户仍缺少把新增条件带到下一阶段的入口；普通网页的复制和打开也分成两个动作。下一轮优先补这两处，不扩展站点数量。真实账号结果和六题盲评留待本人。

## 2026-11-22 · 第三轮 · 用户补充条件与手动交接

**目标与分工**　G1/G2/G3 在暂停的独立作答或质询阶段允许补充判断条件，记录归属，后续新任务使用；G1/G4 合并复制与打开原页的重复操作。DeepSeek 分别承担协议与存储、界面与交接、独立浏览器验收。开发后须比对新增条件前后两份已有原文、下一轮两席的实际提示及最终报告，不只看按钮是否出现。

**结果与复验**　从最终工作树复跑，52 个核心与标签用例、61 项手动路径浏览器检查、13 项补充条件与交接检查均通过。自动路径在预授回环权限的测试副本通过全部检查。已直接核对真实 DOM 上两席共七次提交、逐席表态、最终保存与导出的数据。剪贴板逐字等于当前席位提示。两次交接只打开一个目标标签；重复打开扩展使用同一工作台，实测保留场次 URL。新条件在本轮已有提示中没有出现，在后续两席的质询提示、刷新后的记录、最终报告与 Markdown 中均可找到。[补充条件界面](evidence/guidance.png) · [导出样本](evidence/sample-report.md)

**失败与修正**　为验收预先创建的场次只切了 URL 片段，测试页未重新读取场次，改为重开该路由后核实状态。剪贴板验证改用独立浏览器配置并聚焦工作台，逐字比对，取消跳过。原定演示端口 8765 已有其他服务使用，预设与指引改为 8877，已取到带样本标识的 HTTP 页面并释放本次服务。

**停止决定**　完成三轮后交付本人试用。当前最有价值的新证据是常用真实账号跑一场、原生授权框体验，以及六题盲评中是否比单模型和普通汇总多纠正了错误。样本页无法替代这些判断。九个公共网站目前均为手动交接；第三席、任意远程站点自动驱动、附件、可选裁判与自定义轮数未交付。未运行线上发布或远程推送。试用后根据具体卡点重排优先级。

本次 OpenCode 执行进程和 30 分钟自检均已取消，试验服务已关闭。

## 2026-11-22 · 第四轮 · 界面与实际操作

**目标**　G1/G3/G4。缩短重复开场与手动交接的路径，给桌面和小屏做适合长时间阅读的玻璃风格界面；把页面文字改成能直接说明下一步的中文。

**参照与分工**　总指挥在隔离 Chromium 加载了参考项目的 popup.html，核对了推荐组合、带图标的成员选择、底部操作和目录入口。视觉样式、品牌标识、文案、交互、小屏导航、回归检查分别派给本机 OpenCode Go 的 DeepSeek V4.1 Flash high。验收以实际提问、回填、互评、表态和查出处为准，并对照浅色、深色和窄屏截图。

| 使用场景 | 与参照版的比较 | 本轮取舍与复验 |
|---|---|---|
| 同一组 AI 再讨论一题 | 原版首页有一键组合和站点图标，旧工作台每次重新选人，多个图标只有相同首字母。 | 九个站点采用本地图标。首次自己选，一次成功开场后记住该组合，下一题直接输入；已有草稿优先。 |
| 手动交接 | 原版将操作放在每条消息附近。旧工作台在每张卡平铺了复合按钮、单独打开、复制和站点首页，终态还出现后台会拒绝的操作。 | 待答卡主要显示去原站、录入回答，其他操作折叠；指出下一位待答成员。独立作答和质询中，一方误粘贴、另一方还没提交时可改正，旧文本留存。下一阶段及表态锁定。跳过保留的草稿可阅读和复制，不能计入答案。 |
| 窄屏查看与输入 | 参照版的讨论目录可收起；旧版 390px 宽时，空历史区约占顶部 290px。 | 用约 55px 的顶栏保留新讨论和历史入口，展开可搜索，选中回到正文，Escape 可关闭。390px 与桌面实测均无横向溢出。 |
| 最后怎么看结论 | 原版有裁判报告。旧工作台一开报告先读轮次、成员和版本信息，建议在下面。 | 先看建议、逐席态度和仍未解决的条件，可从引用跳到原话。完整报告和导出继续保留；没有候选答案时显示已有材料。 |

**视觉与文字**　桌面和连接设置采用浅、深两套玻璃材质，正文用稳定底色；首页双环为本机离线渲染。支持减少透明度、减少动效和键盘操作。按 leozhou-blog-writer 的规则删去重复引导，把开头“把一个问题，交给两席独立判断”改成“想讨论什么？”。首页和设置文案已在本机留档。[浅色](evidence/glass-light.png) · [深色](evidence/glass-dark.png) · [窄屏](evidence/glass-mobile.png) · [结果页](evidence/glass-result.png)

**失败与修正**　第一稿小屏历史占位太大；玻璃素材首稿像平面色块，第二次用实际光照渲染。复核还发现跳过后错误承诺可以补录、换成员提示与操作冲突、展开编辑时重复跳过及可选控件泄露 null。已逐项修复并回放。未提交草稿和已提交更正分开保存。

**验收与停止**　57 个核心及标签用例通过。独立 Chromium 回放通过 61 项手动流程、39 项交互与外观检查、37 项操作修复验证、25 项回答更正验证；补充条件与本机自动接力也通过。复验覆盖浅色、深色、390px 窄屏、提交状态、重新打开、逐席确认与引用跳转。本机自动接力依然使用预授回环权限的测试副本与确定性页面。本轮只对比参考项目的实际界面、入口与代码，没有用真实账号重测公网自动收发。01:01 自检已确认仍有周额度，并核对活跃执行者；交付后已停止本轮派工和自检。
