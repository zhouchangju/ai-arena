# 自用多 AI 辩论工作台需求文档

**初稿** 2026-11-21 · **实现基线** macOS 原生工作台。给手边已有多个网页 AI 账号的人提供一个易用的中文工作台。用户只发起一次，工作台安排轮次、传递各席的材料和答复，并标明需要人工中转的席位和步骤。参与讨论的模型各自作答、互相质疑、起草或修订候选、确认同一版本，负责形成实质判断。工作台按保存的原文和表态呈现讨论结果。

## 一次讨论应该怎样结束

假设问题是“我的个人笔记工具值不值得先做移动端？我只有两个周末。”首轮 A 独立建议做移动端，因为采集常发生在路上。B 建议先补桌面检索，因为现有数据只证明检索慢。互评时 B 指出“常在路上记录”仍待用户证实，A 接受质疑，把主张改成“先用手机快捷入口验证采集频次”。由一席把这次修正和优先级反转的条件写入候选，其他席位据此表态。双方若仍有分歧，工作台展示候选和原始异议。

用户在结论页先看模型提出的候选和各席对该版本的表态，再按需展开成立条件、反例、未决分歧及历史。点出处可回到某位 AI 的某一次发言。模型转述的事实保留“待核实”状态，原文引用用于追溯该主张。

## 首版范围与交互

当前 macOS 工作台支持 ChatGPT、Gemini、DeepSeek。开场默认选中三席，也可选两席。互评上限默认 3 轮，可设 1–5 轮；每一轮从互评开始，之后起草或修订候选并请各席表态，独立作答是前置阶段，不计入互评轮次。独立作答、互评和候选确认各自留有原文与出处。下表描述产品需求和验收条件，已实现的操作以[试用指引](try-it.md)为准。

| 编号 | 用户可观察的要求 | 验收方式 |
|---|---|---|
| R01 建场 | 开场收集问题、可选附件、参与席位和互评上限。用户可以粘贴多张截图、从 Finder 拖入或选择文件，预览并移除材料，确认接收席位。 | 连续粘贴两张截图，移除一张，再加入文本文件。检查材料顺序、接收席位和开场限制。 |
| R02 独立回答 | 给每一席单独的新对话、相同题面和同一组开场材料。先完成的一席显示原文，慢席继续。首轮没有人提前看到别人的答案。 | A 秒回、B 慢回，逐席核对首轮提示、文本附件正文和图片顺序。模拟一席缺图，检查该席是否停下来等人处理。 |
| R03 交叉互评 | 本轮冻结后，工作台把其他席位的原文与出处放入各席的互评提示。由模型指出最强依据、反例，以及自己维持或修正的主张。用户可暂停后续派发并查看该阶段的实际提示。 | 将唯一反例放在 B 首轮中段，核对 A 收到的提示含该反例和出处，并能回看 A 的答复，确认它是否回应了该反例。 |
| R04 收敛与停止 | 由指定成员起草或修订候选结论，让每位参与者针对同一版本明确选择同意、有条件同意或反对，并写理由。保留实质反对、所附条件、缺席和无法解析的表态。 | 分别回放全体同意、一人沉默、一人反对、同意但附相反条件四例；只有第一例可显示全体同意。修订候选结论后重新确认，旧表态留在历史里。 |
| R05 结论 | 显示模型提出的候选、成立条件、最强反例、已解决与未解决的问题、每席对当前版本的态度和模型提出的下一步。重要判断可点回段落，外部资料链接区分已核与模型提供。 | 伪造轮次 ID、只出现于首轮的异议、两位都引用同一条未经核实的信息，分别验证拒绝错误引用、保留早期异议、标明共同依赖。 |
| R06 进度与接管 | 讨论页显示当前阶段和逐席进度。自动席在原站看到本轮用户消息后标记发送成功，并同步后续网页正文；完整回答进入本轮记录。每席可在原页核对、转为手动或跳过。暂停停止后续派发。 | 让 A 先完成、B 分段生成、C 的原页不可用。核对 B 的正文变化、A 的已保存原文和 C 的接管操作，C 手动回填后可继续。 |
| R07 阅读与历史 | 讨论中并排显示各席原页。报告窗口按需展开成员答案、往轮和逐项引用。工作台关闭后可回原场，报告可复制和导出 Markdown。 | 对照两轮再返回结论不会重发；导出离线可读，含题面、成员、轮次、异议、停止原因和引用编号。 |
| R08 私人使用 | 本场记录保存在 macOS 本机。各席接收本轮所需题面和材料，实际提示及回答原文留存以便核对。广告、评分、推广水印、外部榜单和营销链接一律排除。 | 核对不同场次的原文、提示与导出各自归属。检查应用界面、导出和网络请求中的内容接收方及推广元素。 |
| R09 站点能力 | 逐站记录手动中转、填写、发送、读取与完成判断的实测覆盖。各席原页按账号能力提供模型选择，未识别具体型号时只标站名。 | 模拟只支持填写的站点，仍可参加人工流程；不得把未识别模型标为某旗舰版本。 |

### 讨论页上的三个决定

- **开始时**，用户只需填问题、选成员、点开始。应用在各席 WebKit 原页按站点状态发送首轮提示。登录由用户在应用内按站点流程完成。自动派发受阻时可按席接管并补录本轮原文。
- **进行中**，默认读最新一轮。每位成员的卡片用固定类别显示“生成中”“已收到”“需要你处理”等状态，具体原因放在第二行或悬停说明里。进入互评后突出显示“B 质疑了 A 的哪句话”；若一席失败，只在这张卡上处理，不用重新开始整场。可核对每席的实际提示与已保存原文。
- **结束时**，先呈现模型候选和有条件一致、仍有分歧、证据不足或部分完成等状态。按需展开争点及原文。修订候选时创建新版本，往轮表态仍可回看。

## 什么时候值得多跑一轮

首轮独立回答之后至少做一次有效的交叉互评。起草席按争点提出候选，各席对候选原文明确表态。工作台依据表态和互评上限推进流程。有明确反对或附加条件且仍有轮次时，可把候选和争点送回各席定向互评，再请起草席修订并重新确认。若所缺事实需要用户提供，报告保留模型提出的条件和待回答的问题。达到上限、用户停止或参与不足时，交付当前结果并保留停止原因。手动席的等待不耗用互评轮次。

## 怎样验收工作台

按 R01–R09 检查实际发送与收回的提示、回答和出处，确认用户能从当前候选回看互评，也能在单席或工作台中断后继续。报告和导出应回到同一候选版本，保留各席的条件、反对、缺席和停止原因。核对全体一致时，每席都应明确接受该版本。真实站点验证和确定性样本回放分别记录。

首批六题已采集讨论样本并制作匿名对比卷。用户可自愿用它比较同题独立回答、一次普通汇总与完整讨论的内容和交互成本。产品试用和交付按上面的工作台验收执行。 [六题对比方法](qa/decision-quality-blind-review.md) · [采集记录](iterations.md)

## 明确移除与保留

| 自用版决定 | 理由及检查 |
|---|---|
| 排除商店评分、延后评分计数、推广页/群二维码、截图品牌条、指向上游的更新提醒 | 干净配置和已有历史配置都验证；检查界面、导出以及运行时请求。法定署名保存在许可证或第三方声明里。 |
| 排除 PPT 工坊、PPT-SUPER、打卡成就、外部模型实力榜、角色皮肤包 | 这些功能服务制片或展示。检查打包产物也未携带模板资产及相关权限。 |
| 保留来源、打开原页、必要的登录说明、单席排障、可读的本地帮助 | 来源和排障帮助用户判断答案可靠性。区分用户要求的参考链接、模型引文与作者导流。 |
| 后续候选保留详细记录 | PDF、Office 原文件、个人模板、角色、顺序接力、摘录、长图、更多站点有各自验收方法。是否进入开发由实际使用决定。 |

各项参考需求及反向验收见 [Arena 功能清单](arena-features.md) 和 [Panelize 功能清单](panelize-features.md)。新协议、引用与质量实验属于本项目设计。
