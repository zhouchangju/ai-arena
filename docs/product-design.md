# 自用多 AI 辩论工作台需求文档

**设计日期**　2026-11-21。目标用户是正在判断一个问题、手边已有多个网页 AI 账号的人。一次发起后，让工具代管轮次、组织反驳和汇总。在支持自动收发的组合上，正常流程从开始一直走到结论；遇到需要人工操作的网站，界面提前标明是哪一席、哪一步。

## 一次讨论应该怎样结束

假设问题是“我的个人笔记工具值不值得先做移动端？我只有两个周末。”以下是设计示例。首轮 A 独立建议做移动端，因为采集常发生在路上。B 建议先补桌面检索，因为现有数据只证明检索慢。互评时 B 指出“常在路上记录”从未得到用户证实；A 接受质疑，把主张改成“先用手机快捷入口验证采集频次”。结论就应当写出这个改变，以及“如果采集次数高而桌面检索使用少，优先级会反转”。如果双方对优先级仍有分歧，工作台照样交付一份有条件的回答。

用户最后打开的是一页短答：**建议做什么，依据是什么，什么新事实会改变这个判断**。点依据可回到某位 AI 的某一次发言。模型转述的事实保留“待核实”状态，原文引用只证明该成员确实这样说过。

## 首版范围与交互

以下为建议的首版边界。默认两位不同成员，一场可配置质询上限，起始值为两轮；独立作答、质询、确认候选结论是三个不同动作。三席、角色帽、顺序接力、图片等细项的取舍见两份参考功能清单。支持平台按实测公布。

| 编号 | 用户可观察的要求 | 验收方式 |
|---|---|---|
| R01 建场 | 首页保留问题、可选背景/判断标准、参与者、开始。开始前显示哪些网站会接收原问题、其他成员发言，哪些需要手动收发。 | 空题、只有一席、同一人被重复添加时给出具体提示。确认两席后能预览各自收到的内容。 |
| R02 独立回答 | 给每一席单独的新对话与相同题面。先完成的一席显示原文，慢席继续。首轮没有人提前看到别人的答案。 | A 秒回、B 慢回，抓取本地发送记录确认两份输入一致、均不含 A 的答案。 |
| R03 交叉质询 | 完整回答到齐后自动互换对方的具体主张。要求指出最强依据、最有影响的反例、自己维持或修正了哪条主张。用户可暂停，补充条件后再继续。 | 将唯一反例放在 B 首轮中段，A 必须看到该反例；评价结果可标“未回应”，不能仅因收到了文字就视为解决。 |
| R04 收敛与停止 | 由指定成员起草候选结论，让每位参与者针对同一版本明确选择同意、有条件同意或反对，并写理由。只要有实质反对、条件未纳入、缺席或表态无法解析，就保留该状态。 | 分别回放全体同意、一人沉默、一人反对、同意但附相反条件四例；只有第一例可显示全体同意。修订候选结论后确认重新计数。 |
| R05 结论 | 显示简明答案、成立条件、最强反例、已解决与未解决的问题、每席最终态度、建议的下一步。重要判断可点回段落，外部资料链接区分已核与模型提供。 | 伪造轮次 ID、只出现于首轮的异议、两位都引用同一条未经核实的信息，分别验证拒绝错误引用、保留早期异议、标明共同依赖。 |
| R06 进度与接管 | 讨论页上方显示当前阶段、各席进度和暂停。每席提供原页、查看本次提示、重读、补录、跳过或结束。暂停停止后续派发，已在原站生成的内容可继续读回。 | 让 B 登出、限流、关闭标签或改版。A 的原文仍在，B 可单席恢复、粘贴或明确缺席。两席中缺一席则无法形成双边共识。 |
| R07 阅读与历史 | 默认聚焦当前问题，按需展开成员答案、往轮、逐项引用，或切为并排。工作台关闭后可回原场；支持查找、复制和本地 Markdown 导出。 | 对照两轮再返回结论不会重发；导出离线可读，含题面、成员、轮次、异议、停止原因和引用编号。 |
| R08 私人使用 | 本场记录保存在扩展本地。发送时只带预览中的素材，允许修改转发副本；原文保留。个人可删除指定场次。广告、评分、推广水印、外部榜单和营销链接一律排除。 | 两场不同问题混合恢复后仍可分别删除。检查首次使用、运行中、结束、导出及空闲网络请求；不得出现上游推广或未选择的内容接收方。 |
| R09 站点能力 | 平台卡分别显示支持手动中转、填写、发送、读取、完成判断及最近实测日期。用户能在普通标签里选择自己账号可用的模型，未识别时只标站名。 | 模拟只支持填写的站点，仍可参加人工流程；不得把未识别模型标为某旗舰版本。 |

### 讨论页上的三个决定

- **开始时**，用户只需填问题、选成员、点开始。更换裁判、轮数上限和背景说明折叠到设置中。手动席直接给出“复制本轮问题 → 打开原页 → 粘贴回答”，粘贴范围仅限用户选择的本轮文本。
- **进行中**，默认读最新一轮。每位成员的卡片固定显示“正在生成”“收到完整回答”“需要你处理”等状态。进入质询后突出显示“B 质疑了 A 的哪句话”；若一席失败，只在这张卡上处理，不用重新开始整场。用户补充的新条件有生效轮次。
- **结束时**，先呈现推荐回答；有条件一致、仍有分歧、证据不足、部分完成分别写明。点“为什么”才展开争点及原文。选择继续讨论会创建新版本，旧报告可回看。

## 什么时候值得多跑一轮

首轮独立回答之后至少做一次有效的交叉质询。裁判按争点整理出可明确表态的候选结论，各席对其作答。全体接受且关键条件已纳入时结束；仍有能通过推理或已有材料解决的争点，并且轮数有余量时，下一轮只发该争点。缺的若是用户才能提供的事实，直接给条件结论和待回答的问题。达到上限、无新依据、用户停止或剩余有效成员不足时都交付当前结果，保留停止原因。手动席的等待不耗用质询轮数。

建议用两档基线评估“辩论有没有多带来东西”：同题最好的独立回答，以及相同独立回答经一次普通汇总得到的结果。首批选择六个真实但可分享的题，覆盖可核对事实、取舍和证据不足各两题。隐去来源、随机顺序，由本人比较关键事实、被纠正的错误、遗漏的反例和行动建议，同时记录耗时、网页交互次数与人工步骤。作为首次试用目标，至少四题相对两条基线均有具体改进，且零次虚构一致或丢失决定性异议。未达到就查提示、材料或流程，决定是否值得加站点。这是产品试验目标，尚无实测评分。

## 明确移除与保留

| 自用版决定 | 理由及检查 |
|---|---|
| 排除商店评分、延后评分计数、推广页/群二维码、截图品牌条、指向上游的更新提醒 | 干净配置和已有历史配置都验证；检查界面、导出以及运行时请求。法定署名保存在许可证或第三方声明里。 |
| 排除 PPT 工坊、PPT-SUPER、打卡成就、外部模型实力榜、角色皮肤包 | 这些功能服务制片或展示。检查打包产物也未携带模板资产及相关权限。 |
| 保留来源、打开原页、必要的登录说明、单席排障、可读的本地帮助 | 来源和排障帮助用户判断答案可靠性。区分用户要求的参考链接、模型引文与作者导流。 |
| 后续候选保留详细记录 | 图片/文件、个人模板、角色、顺序接力、摘录、长图、更多站点有各自验收方法。是否进入开发由实际使用决定。 |

各项参考需求及反向验收见 [Arena 功能清单](arena-features.md) 和 [Panelize 功能清单](panelize-features.md)。新协议、引用与质量实验属于本项目设计。
