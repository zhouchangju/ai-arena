# 试用指引

直接加载即可用：九个原生站点手动中转，本机 A / B 配好后可自动派发。自动接力已用确定性夹具实跑一轮七次提交；真实站点的自动收发未验。对应 G1–G4。

## 1. 加载扩展（约 1 分钟）

1. 打开 `chrome://extensions`，右上角开「开发者模式」。
2. 点「加载已解压的扩展程序」，选仓库里的 `extension/`（含 `manifest.json` 那一层，不是仓库根目录）。
3. 点工具栏图标进入「判断台」。改过扩展文件后，先在卡片上点刷新，再重开工作台。

## 2. 手动跑一场

1. 首页先填「写下问题」，再到「选择两席」点两张不同席位（显示 `2 / 2 已选`），点「开始判断」。
2. 每阶段每席同一套动作：席位卡点「复制提示并打开原页」（一次点击：复制本轮提示并切到这一席的原页，已绑定的原页会复用当前标签）→ 在原站粘贴、发送、等写完 → 全选复制 → 回来点「粘贴回答」，粘进「回答原文」→「提交回答」。不想跳转时，仍可用分开的「复制提示」「打开原站」两个按钮。顺序：独立作答 → 交叉质询 → 候选结论 → 逐席确认 → 结论。
3. 示例问题：`我的个人笔记工具值不值得先做移动端？我只有两个周末。`
4. 质询提示里应出现对方原话和 `[S1 · chatgpt · independent · 第1轮]` 这类来源块；没有就说明取回的文本不对。
5. 候选结论提示的材料逐条带编号。提交时引用了不存在的 `[S#]` 会被拒绝，错误里列出本场有效编号，也不会发起表态；改掉后在「候选结论原文」重新提交。一条编号都不写也能提交，但报告只按草稿算。
6. 逐席确认：选「明确立场」（同意 / 有条件同意 / 反对）→ 在「理由（必填，保存为本轮回答原文）」写理由 →「记录表态」。缺席与沉默都不计为同意。
7. 中途想加约束：先点「暂停」，页面出现「补充判断条件」→ 写下条件（例如“预算上限两万元”）→「保存条件」。条件只写入本场记录，供**之后新建的任务**使用，不改动当前提示也不自动发送；已保存的条件随本场记录保留。它只在独立作答与交叉质询两段可填，恢复讨论后可继续提交。

## 3. 读结论与导出

「结论」页里的 `[S#]` 可点，会跳到「历次发言」的对应原文并高亮。先看「引用校验」：没有可核实来源即按草稿处理。「导出 Markdown」保存 `判断台-问题-日期.md`；「复制结论」只复制报告文本。左侧「历史场次」可重开，刷新或关掉再开都不会重发提示；「删除记录」只删本机。

## 4. 本机两席自动（可选）

在**仓库根目录**另开一个终端，启动夹具服务并保持运行（端口用 `8877`；本机已有的其他服务端口不要动，若 `8877` 被占用，换一个空闲端口并让两席地址与启动命令保持一致）：

```bash
python3 -m http.server 8877 --bind 127.0.0.1 --directory tests
```

浏览器打开 `http://127.0.0.1:8877/web-driver-fixture.html?seat=A` 能看到「Web Driver 夹具」页，说明服务已就绪。

然后按这个顺序配好两席并启动：

1. 「连接设置 · 本机网页」→ 点「填入本机测试页配置」（两席地址分别是 `?seat=A` 与 `?seat=B`，端口 `8877`）→ 两席分别点「保存本席」。Chrome 会弹原生权限框，得你在自己的浏览器里点允许；无头测试用的是临时副本（回环地址已预授权），生产目录没改。
2. 回到场次页，新建一个场次（不要复用旧场次）：首页写问题 →「选择两席」点「本机 A」和「本机 B」→「开始判断」。
3. 在场次页点「开始自动化」，只驱动已配置的两席；可「停止自动化」或「刷新自动状态」。

夹具回答由本地哈希生成、带 `[FIXTURE seat=…]`，是确定性样本不是模型输出，别写进真实报告。
