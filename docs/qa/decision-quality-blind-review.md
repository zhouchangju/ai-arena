# 六题判断质量盲评

**目标 G2、G3（R02–R05）。** 本人拿到每题匿名回答和计分表，可以先独立比较实际答案，再回看每条改进来自哪次质询、投入了多少人工操作。六个情境及其数据均为虚构，可以公开分享。题库各含两道可核对事实、取舍和证据不足题。 [题库和参考判据](decision-quality-questions.json)

## 采集

采集者和评分者由不同的人担任。评分者只接触匿名卷，采集者保管身份、原文和运行记录。把实际数据放进仓库外的私有目录。

1. 开始前记录参与者、可确认的模型及模式、质询上限、普通汇总用的模型。六题保持配置一致。每题使用新的 Arena 场次和站点对话，只发送题库中该题的 `prompt`。保存 Arena 原始提示、每席首次回答、质询、候选版本、表态、停因以及原生导出。
2. 同一题的全部首次回答直接作为独立回答候选。将同一份题面和全量首次回答原文按席位代号送进一个新对话，使用负责 Arena 候选起草的同一模型及模式做一次普通汇总。开场时固定模型和提示，保留实际提示。结果输出后即结束这条基线。
3. 保存每题三类材料。独立回答取首次完整正文。普通汇总取这一次答复的正文。Arena 取最终向用户展示的短答、依据、反例、限制和行动。工作台界面标题、站名、引用链接、逐席状态等只作识别或过程审计的包装可去除。若正文用某席意见作依据或表达分歧，保留原句及其逻辑，可遮盖可识别称呼。正文若自带独有的流程分段，保留有实际判断信息的段落，并在发卷前检查是否仍能辨认来源。不得重写结论、删掉缺点或补证据。
4. 逐路记录完成时间、网页交互次数和人工步骤。完成时间从该路首个动作到答案可用，含等待。网页交互按在站点的打开、发送、读取等动作记数，打开与发送各计一次。手动操作单独记数，每次人为复制、切换、发送、核对或回填各计一步。独立各席按自身运行记，汇总记录应另记首次回答的共用成本并注明，Arena 按全流程成本记。保留逐事件底稿，避免把跟踪动作算进产品操作。
5. 缺席、截断或失败保留在私有底稿，记录原因和复跑次数。没有足够真实候选时不发完整评级卷。若问题正文明确要求外部事实则统一核实，本题库只用题面材料；采集者不在运行中补背景或引导答案。真实采集有额外题面或配置偏离时，记录偏离并单独审看。

提交一次普通汇总时使用以下文本，再附上该题原文及逐席完整回答。

```text
请根据题面和给出的独立回答，用中文给出一份可直接交给决策者的最终回答。写出你的判断、依据、最强反例或未知项，以及可行的下一步。指出实际分歧和结论成立的条件。仅使用给出的材料。

题面
（粘贴原题）

独立回答，依次使用同一组中性的编号
（粘贴全部首次回答原文）
```

## 发卷

准备私有 UTF-8 JSON 清单。顶层 `questions` 必须包含 `Q01` 至 `Q06`，每项是候选对象数组。每题至少两份 `independent`，一份 `synthesis`，一份 `arena`。以下只是对象字段示例，需换成真实路径和实测数据。

```json
{
  "variant": "independent",
  "model": "实际站点、实际模型及模式，或明确记录未知",
  "source_ref": "场次、轮次、席位及消息编号",
  "raw_file": "captures/Q01/seat-1.md",
  "elapsed_seconds": 42.5,
  "web_interactions": 3,
  "manual_steps": 2,
  "lines": [1, 30],
  "redact": ["原文中存在的站点或模型名"]
}
```

`raw_file` 相对于清单，指向未改的原文。可选的 `lines` 选取连续正文，使用从 1 开始的闭区间，默认保留全文。可选的 `redact` 按字面遮盖标识。顶层可加 `identity_terms` 补充模型别名、供应商域名、界面用语或实验代号，检查发现这些词残留时会拒绝出卷。逐份检查是否还保留语义指纹、署名、外链或独特前缀。流程特征有时可从答案内容推断，评分者应登记猜测和线索。

```bash
python3 docs/qa/make_blind_packet.py /私有实验/manifest.json /私有实验/第一次发卷
```

输出目录须是新目录。程序逐题随机分配候选字母。`review.md` 是唯一交给评分者的文件。`private-key.json` 包含来源、原文哈希、评分参考、对应身份和成本，采集者保留到交卷后。发卷时可再记下 `review.md` 的 SHA-256，用来确认评分对应哪次随机排列。全卷交回前不打开题库的 `key`，也不查看原站、运行记录和身份映射。

## 计分与复核

评分者给每个候选按事实、纠错、反例、行动四项各 0–2 分，并保存排序与原句。每题先基于题面完成比较，再解封题型判据、来源与成本。揭晓后按盲评排序选最强独立候选，若最强独立并列，以更难超越的一份作为对照。涉及具体算术，则和参考判据核实；若影响评级，增记复核理由及改分，保留原始盲评。

逐题填写 `题号 / 最强独立 / 普通汇总 / Arena / 对两条基线各自的具体改善或退步 / 耗时、网页交互和人工步骤 / 两条过程审计`。有具体改善需要指出实质纠正的错误、补上的决定性反例或证据、避免的过度推断，或可改变决定的行动标准，并引用候选原句。同类事实的重复、语言更顺、篇幅更长都不能单独算改善。新引入的关键错误与擦掉的决定性条件也要计入判断。

过程审计用实际候选版本、席位表态和全程原文检查两件事。

- **虚构一致**：报告声称全体接受，而至少一席缺席、截断、反对、没有明确接受同一版，或接受所附条件仍未纳入。
- **丢失决定性异议**：质询或表态已有异议，若成立就会改变主张、信心或行动，但最终报告遗漏且没有解释为何能够排除。

首次试用达到产品目标需要六题完整评分，至少四题对两条基线都各有具体改善，同时两类过程问题均为零。报告附上失利题及人工成本，并写明盲评中可能泄露来源的候选。 [产品设计的试用目标](../product-design.md)

当前可验证题库、发卷和身份隔离。真实候选、成本、全程审计和本人盲评须在实际采集后才能填写。
